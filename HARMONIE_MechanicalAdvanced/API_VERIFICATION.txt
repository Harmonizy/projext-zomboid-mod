HARMONIE - Mechanical Advanced -- API Verification Report
===========================================================
Every distinct API call used across this mod's Lua files, checked
against REAL vanilla source that actually runs (not decompiled .class
bytecode -- see the getFrontEndHealth() incident below for why that
distinction matters). Each entry cites the exact vanilla file:line
where the same call is used successfully, or notes when confirmation
instead comes from our own live in-game testing.

Confidence tiers used below:
  [VANILLA]  Found used in real, shipped vanilla Lua source (strongest).
  [LIVE]     Not found in vanilla Lua source, but confirmed working by
             actually playing the mod in-game and observing the effect.
  [MOD-SRC]  Copied from a third-party mod's real source code (not
             vanilla), and separately confirmed by our own live testing.
  [FAILED]   Looked real (existed in the .class file) but is NOT
             actually callable from Lua -- kept here as a permanent
             warning, not something we use anymore.

CONFIRMED NOT TO WORK -- DO NOT REUSE
========================================
part:getConditionMax()
  [FAILED] Exists on InventoryItem (Vehicles.lua:1182 etc, always on
           "item", never on "part") but does NOT exist on a vehicle
           PART object. Calling it on a part throws immediately.
           Vanilla itself always hardcodes 100 for part condition max
           (e.g. part:setCondition(100)). We made this mistake twice
           (PerfExhaust and Bullbar) before catching it from
           console.txt -- "attempted index: getConditionMax of
           non-table: null" / "Object tried to call nil".
  Fix used: replaced with the literal number 100 everywhere.

vehicle:getFrontEndHealth()
  [FAILED] This is the important one. The method genuinely exists in
           the compiled zombie/vehicles/BaseVehicle.class (confirmed by
           extracting projectzomboid.jar and grepping the class file
           for method name strings) -- but is NOT exposed to Lua at
           all. Calling it threw "Tried to call nil" every single time,
           on every vehicle, even wrapped in pcall.
           LESSON: a method's presence in decompiled bytecode is NOT
           evidence it's callable from Lua. PZ's Lua binding is an
           explicit exposure list, not automatic reflection over every
           public Java method. Only an actual working call site in
           real, shipped Lua source (or genuine live in-game testing,
           as with getScriptManager():getVehicle() above) counts as
           real evidence. Every [VANILLA] entry in this report was
           found this way on purpose, specifically to avoid repeating
           this mistake.
  Fix used: abandoned trying to detect a specific collision from Lua
           entirely -- there is no Lua-exposed collision event or
           getter anywhere in vanilla (grepped every file, zero hits).
           Redesigned Bullbar around vehicle:getCurrentSpeedKmHour() +
           the real Update.Tire mechanic instead (see above).

calendar:getDayOfMonth() -- i.e. getGameTime():getCalender():getDayOfMonth()
  [FAILED] getCalender() itself is real and used throughout vanilla,
           but getDayOfMonth() is not a real method on whatever it
           returns. Crashed every single part install with "Object
           tried to call nil in RecordInstaller".
  Fix used: getGameTime():getDay() instead (see confirmed entry above).


HOW THIS WAS BUILT
====================
For every API call in the 6 Lua files under 42/media/lua/, searched
C:\Program Files (x86)\Steam\steamapps\common\ProjectZomboid\media\lua
for the exact same method/field name actually being called in real,
shipped vanilla source (not just present somewhere in a string) --
using Grep on the .lua files directly, never on decompiled .class
files, per the lesson above. Where vanilla had no equivalent at all
(the two getScriptManager()/Load lines), fell back to the next-best
evidence available: a real third-party mod's source (tsarslib, cached
locally) plus this mod's own actual successful in-game test runs.
