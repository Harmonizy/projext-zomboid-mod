==============================================================================
RULES ENGINE -- how a recipe's real stats/name decide which procedures it
needs (gen_craftdata.js addFinishingSteps() + applyAssemblyOverrides(),
the actual source of truth)
==============================================================================

A) Sharpness -- Swinging weapons only, and only if CriticalChance > 0
   (CritChance = 0 skips this category entirely). SINGLE-BAND-SELECT by
   CriticalChance (exactly one procedure, not cumulative):
     CritChance < 20        -> SharpenEdge
     20 <= CritChance < 40  -> StropLeather
     40 <= CritChance < 60  -> QuenchHarden (was PrecisionGrind)
     CritChance >= 60       -> AnnealMetal (was ForgeShape)

B) Piercing -- Spear/Stab weapons only, same CritChance > 0 gate and band
   shape as A:
     CritChance < 20        -> KnapHead
     20 <= CritChance < 40  -> TaperPoint
     40 <= CritChance < 60  -> QuenchHarden (shared with A, was PrecisionGrind)
     CritChance >= 60       -> AnnealMetal (shared with A, was ForgeShape)

C) Handle -- SINGLE-TIER-SELECT by MaxRange (the highest qualifying tier
   ONLY -- NOT cumulative; a handle can only be attached one way):
     MaxRange >= 1.6              -> MakeRivetedHandle, TightenBolts
     else MaxRange > 1.4          -> MakeLongHandle, ReinforcedBind
     else MaxRange > 1.2          -> MakeHandle, WrapBind

D) Balance -- CUMULATIVE by PushBackMod:
     PushBackMod >= 0.3  -> + HammerNails
     PushBackMod >= 0.5  -> + CounterweightHead
     PushBackMod >= 1.0  -> + WeldMetal

E) Structure -- CUMULATIVE by KnockdownMod:
     KnockdownMod >= 2  -> + RivetPlate
     KnockdownMod >= 3  -> + DrillCore

F) Toughness -- CUMULATIVE by ConditionMax:
     ConditionMax > 5   -> + WrapCloth
     ConditionMax > 10  -> + WrapLeather
     ConditionMax > 15  -> + StringSinew
     ConditionMax > 20  -> + WeaveWire

G) Wear Resistance -- CUMULATIVE by ConditionLowerChanceOneIn:
     ConditionLowerChanceOneIn > 10  -> + CoatMud
     ConditionLowerChanceOneIn > 20  -> + FireTreat
     ConditionLowerChanceOneIn > 30  -> + CoatWax
     ConditionLowerChanceOneIn > 40  -> + SurfaceCoating
     (real note: nothing in the current 248-recipe craftable pool
      actually exceeds 40, so SurfaceCoating is defined but currently
      never required by any real recipe.)

H) Assembly -- NAME-BASED, not stat-based. A real item whose OWN NAME
   describes a specific attached/constructed component gets that
   component's procedure INSTEAD OF whatever Sharpness/Piercing (A/B)
   would otherwise assign -- removes any of SharpenEdge/StropLeather/
   QuenchHarden/AnnealMetal/KnapHead/TaperPoint already picked, then adds
   the matching Assembly procedure. 4 specific named items get a fixed,
   EXCLUSIVE override -- their entire procedure list becomes just this one
   procedure, since the item itself already IS the raw material (a bottle
   you smash, a branch you snap, a plank you saw, glass/tools wrapped in
   cloth by hand, no tool needed) -- no other rule (C-G) applies on top:
     Handiknife/GlassShiv/Toothbrush_Shiv/HandFile -> WrapClothImprov (no tool)
     HalfPlank -> SawWood (tool only, no material consumed)
     SmashedBottle -> SmashBottle (no tool, no material -- just smashed by hand)
     ShortTreeBranch -> BreakBranch (no tool, no material -- snapped by hand)
   Everything else matches by real NAME SUFFIX and is ADDITIVE (only
   Sharpness/Piercing get swapped out, other categories still apply), e.g.
   any "*_Nails" item -> AssembleNails, any "*_Bone"/"BoneClub*" item ->
   AssembleBoneSpike, "*_BarbedWire"/"*BarbedWire" -> WrapBarbedWireAssembly,
   etc. -- see gen_craftdata.js's ASSEMBLY_PATTERNS for the full real-name
   lists). Real result: 75 of the 248 craftable recipes get an Assembly
   override; this also made SurfaceCoating currently unused (the only 2
   craftable items that ever qualified for the top crit band,
   BucketMace_Metal/BucketMace_Wood, are Assembly-matched instead) --
   AnnealMetal is therefore ALSO currently unused by any real generated
   recipe (same real situation ForgeShape was already in before it moved,
   confirmed by regenerating and diffing -- 0 recipes land in the top crit
   band via this rule right now, purely a real-data outcome, not a bug).
   ForgeShape ITSELF is not unused, since the Blacksmithing/Metallurgy chain
   below and the "Spike" name-based override both still use it directly.

A recipe's final procedure list is the UNION of every rule its own real
stats/name trigger across all 8 stat/name-driven categories -- e.g. a long,
heavy-swinging, high-crit sword can require procedures from A, C, D, F, and
G all at once. Real range across all 248 recipes: 1 to 12 procedures per
recipe.

NOTE: every procedure, with no exception, also requires the character not
be tooDarkToRead() (the same real check vanilla's own crafting window uses
to grey out a recipe in the dark) -- shown as a "too dark" missing-
requirement line like any other, and re-checked every tick while the timed
action is running (it stops if the light drops out mid-action, e.g. a torch
running out).

METALLURGY CHAIN (added 2026-09-27) -- 6 new material items, hand-
authored recipes (gen_craftdata.js's METALLURGY_RECIPES, NOT generated
from the weapon table)
==============================================================================

Read straight from real vanilla B42 blacksmithing (recipes_blacksmith_
bar.txt / _other_metals.txt / entity_forge_i/ii/iii.txt):
  MaterialLump          (no base item) -> StartFire, MeltMetal
  MaterialBar_Uncommon  (base=MaterialLump) -> StartFire, PourMold, CoolCast
  MaterialBar_Rare      (base=MaterialLump) -> StartFire, PourMold,
                         ForgeShape, CoolCast, WeldWork
  MaterialBar_Epic      (base=MaterialLump) -> StartFire, PourMoldLarge,
                         ForgeFold, CoolCast, WeldWork, PolishMetal
  MaterialBar_Elite     (base=MaterialLump) -> StartFire, PourMoldLarge,
                         ForgeComplex, CoolCast, WeldWorkComplex, PolishMetal,
                         GrindMetal
  MaterialBar_Legendary (base=MaterialLump) -> StartFire, PourMoldLarge,
                         ForgeVacuum, CoolCast, WeldWorkComplex, PolishMetal,
                         GrindMetal, EngravePattern
Tier is HAND-ASSIGNED (not DPS-derived -- these are materials, not
weapons, so they have no MaxDamage/BaseSpeed at all): MaterialLump=
Common, then Uncommon/Rare/Epic/Elite/Legendary matching each bar's own
name exactly. `category` = "Material", not one of the weapon Categories
tabs -- these only show under CraftUI's All/Available filters (no
dedicated tab exists for materials yet).

Skill levels are exactly as given by the user and were NOT changed;
tools/materials for steps that didn't specify them are this mod's own
judgment call (documented per-procedure in HARMONIE_TWA_Procedures.lua),
using only items/tags already established real elsewhere in this file.
QuenchHarden (Blacksmith:2) is not used by any of these 6 hand-authored
Metallurgy recipes, but IS used broadly elsewhere -- it took over
PrecisionGrind's old slot in Sharpness/Piercing rules A/B (see RULES
ENGINE above), so it's no longer an "unused" procedure overall. AnnealMetal
(Blacksmith:4) is similarly not used by these 6 recipes, and (unlike
QuenchHarden) currently has NO real generated recipe using it anywhere
else either -- see rule H's note above.

Forge-tier gate (CoolCast/QuenchHarden need forgeTier=1 i.e. Primitive-or-
better, AnnealMetal/ForgeShape/ForgeFold need forgeTier=2 i.e. Forge-or-
better, ForgeComplex/ForgeVacuum need forgeTier=3 i.e. AdvancedForge):
vanilla's REAL check is "is the player USING a specific placed Forge
entity" (a separate Entity/CraftBench subsystem this mod's inventory-based
UI doesn't hook into). Approximated instead as "is a real forge of that
tier's own sprite PLACED within 2 tiles" (nearbyForgeTier() in
HARMONIE_TWA_Procedures.lua, matched by real sprite names grep-confirmed
from entity_forge_i/ii/iii.txt) -- discussed with and accepted by the user
as a practical, testable-and-fixable stand-in, not vanilla's literal
mechanism.

New consume shape: `{ options = { {itemType, qty}, ... } }` (MeltMetal only
so far) needs ONE of several real materials, each with its OWN quantity --
unlike the older `itemTypes` shape, which shares one qty across every
alternative. MeltMetal's real options: IronOre x4 / CopperOre x4 /
IronChunk x2 / SteelChunk x2 / CopperScrap x3.

==============================================================================
ICON-VS-TYPE-NAME PITFALL -- recurred repeatedly across 2 rounds of icon
change requests (25 procedures total)
==============================================================================

Roughly half of the icon names requested across both rounds turned out to
be the real item's own TYPE name rather than its actual `Icon` script field
-- the same real, previously-documented pitfall (workflow.txt 8.12: "an
item's Icon field is very often NOT the same as its own type name"). Every
one was grep-confirmed against the real installed game's own
media/scripts/generated/items/*.txt before use; see each procedure's own
inline comment in HARMONIE_TWA_Procedures.lua for the exact real Icon
string used and which vanilla item it was resolved from. One genuine typo
was also caught this way (user's "CeremicIngotCast" -> the real item is
Base.CeramicIngotCast) and one genuine vanilla-side spelling quirk was
preserved rather than "corrected" (Base.Sledgehammer's own real Icon field
is literally "Sledgehamer", one 'm').
